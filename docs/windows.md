The local continuation on 2026-11-08 uses the supplied lockfile: Electron 44.7.0 and electron-builder 26.15.3. Full evidence and remaining acceptance are in [the Windows validation report](2026-11-08-windows-validation-report.md).

## Local validation and desktop smoke test

The bottom-right **Mini / Office** button switches between the full room and a compact desk view. Mini keeps live agent states and click-through details, stops wandering and pets, remembers the choice, and restores the full window size on return. Extra agents get additional compact rows. Settings → Look also exposes Mini and the **Dunder Mifflin setup** switch; disabling the latter restores the previous office decoration. The Scranton-inspired setup uses reception, sales desks, a glass partition, conference table, blinds and paper supplies in the existing warm palette.

`npm run test:mini` exercises the real desktop entry point with an isolated local profile and synthetic agents. It checks native resizing, five return trips without size drift, waiting/idle states, clickable details, reload persistence, seven-agent overflow, and both setup choices. Screenshots and results are retained under `local-runtime/mini-smoke-*`.

Settings → Look → **The Office cast** enables 16 character-inspired names and pixel appearances in both room sizes. Michael, Jim, Pam and Dwight are assigned first, followed by the rest of the Scranton cast. Assignments are stored locally per project/type crew key (including numbered simultaneous colleagues); new arrivals do not reshuffle existing assignments. Explicit names such as `dwight_review` select the matching character. Additional copies receive numbered names. Saved manual crew edits and session aliases take precedence. Clothes keep the character palette while screens, lights and state markers retain live status colors. Click a character to see the original project and provider. Turning off the cast restores the existing avatar/name behavior. The Mini smoke test also validates identity persistence, clothing during state changes, the original project in details, and cast switching; `office-cast.png` previews the complete synthetic roster.

`npm run test:desktop` starts the actual Electron renderer and local server with synthetic Codex JSONL and Kimi bridge events. It verifies two independent characters, testing/editing, permission waiting, and completion, and saves screenshots plus result.json in a new `local-runtime/desktop-smoke-*` directory. The script uses only project-local profiles and test session directories, stays offline, and does not modify user CLI configuration or login startup. Artifacts are retained until cleanup is authorized. It does not replace authenticated real CLI acceptance or tray/mouse/DPI checks.

## Kimi observation

Enable Kimi observation through the tray menu only after approving the user configuration change, then restart Kimi and run a small test task. CLI config uses `KIMI_CODE_HOME` or `~/.kimi-code/config.toml`. Hook scripts are copied out of app.asar into `~/.pixel-office/kimi-helper`; keep these while hooks remain installed. Installation backs up existing config and appends a managed block of 12 hooks. It preserves unrelated configuration and does not make permission decisions.

The generated Windows command invokes PowerShell with literal, quoted Node and helper paths. Paths containing cmd expansion characters are refused rather than producing unsafe commands. A real Windows shell test with spaces, Chinese characters, and an apostrophe in the helper path passed. Two sampled hook invocations took 1,381 ms and 1,355 ms including shell startup; these are not percentile measurements. Windows hooks now get a **two-second timeout** (other platforms retain one second). HTTP operations remain independently limited to 150 ms each and the bridge exits after 700 ms internally. Cold startup under load still needs real CLI measurement.

Installed Kimi 0.34.0 accepted the generated configuration using `kimi doctor` with an isolated `KIMI_CODE_HOME`. After Ken approved installation, the 12 observation hooks were added to the real user config with two-second timeouts. The original config and backup passed byte-for-byte verification, and the real user config passed `kimi doctor`. A synthetic round trip through the installed command completed in 1,438 ms with silent exit and filtered private fields. Restart Kimi sessions to load the hooks. Complete authenticated lifecycle acceptance remains pending.

## Native Windows packaging

Build with `npm run dist:win` (publishing disabled). This now builds `release/CubicleCrew-Setup-2.22.0-kimi.1.exe` natively on Windows, including the Windows timeout correction. The installer is unsigned. Build success does not establish install/uninstall success; those operations have not been run. `npm run dist:win:portable` builds an unpacked portable directory.

The inherited packaged application enables **Start with Windows** on first launch and can migrate an old startup entry. Source development does not enable this automatically. Obtain approval before launching the packaged application on a real user profile or running the installer. Use source mode for development without that startup side effect.

Historical supplied-package status: the Linux build environment used `CSC_IDENTITY_AUTO_DISCOVERY=false npm run dist:win -- --config.win.signAndEditExecutable=false`; it produced an unsigned portable directory without PE metadata/icon editing. Its NSIS cross-build failed at the Wine-dependent uninstaller step. The new native build supersedes that packaging limitation; the original portable ZIP remains unchanged in Downloads.
